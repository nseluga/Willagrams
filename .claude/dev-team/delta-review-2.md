## Findings

### Important
- `Willagrams/Shell/ResultsModel.swift:199-203` — Reliability / Fault Tolerance — the fix is not idempotent: `teardown = nil` (line 200) runs *before* `guard toreDown` (line 202), so after a declined press the screen becomes a nil-teardown screen, and a second press takes the `?? true` default and calls `shell.returnToMenu()` — the original regression, one tap later. Verified by running the delta's own code: a probe test pressing `stale.mainMenu()` twice fails with `(shell.route → .menu) != .menu` on the second press while `practice.match` is still live. Fix: keep the decline sticky — e.g. `private var declined = false`, set it when `toreDown == false`, and make the guard `guard !declined, toreDown else { declined = true; return }` (or equivalently only clear `teardown` when it tore down and gate on a separate spent flag). One extra assertion in `aStaleScreenCannotSendTheNewMatchToTheMenu` (press `stale.mainMenu()` a second time) locks it.
